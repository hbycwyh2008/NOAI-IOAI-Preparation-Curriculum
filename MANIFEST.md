# Repository Architecture Manifest

This manifest describes the maintained repository architecture. It is intentionally not a hand-written exhaustive list of every file because the lesson bank changes over time and a static list becomes stale.

The authoritative file-count and link check is:

```bash
python scripts/validate_curriculum_structure.py
```

## Canonical Source Priority

When two documents appear to overlap, use this priority:

1. `02_Class_Missions/` for lesson content, evidence, and duration;
2. `00_Course_Overview/Detailed_Lesson_Sequence.md` for scheduled session order;
3. `00_Course_Overview/Pacing_Guide.md` for pathway/timing policy;
4. `10_Ready_to_Teach_Pack/` for teacher-facing phase indexes and assessment packs;
5. public or parent/student summaries for communication only.

A phase summary must not maintain a second conflicting lesson body.

## Generated or Compatibility Assets

- `10_Ready_to_Teach_Pack/Runtime_Validation_Record.md` is generated by the Ready-to-Teach validation workflow.
- `10_Ready_to_Teach_Pack/Link_Verification_Latest.md` is generated by the link checker.
- `10_Ready_to_Teach_Pack/Completion_Audit_90.md` is a compatibility pointer only.
- `scripts/normalize_lesson_timelines.py` and `scripts/validate_curriculum.py` are compatibility wrappers that call the current non-destructive validator.
- `scripts/v1_chunks/` contains inert archival fragments. The obsolete workflow that decoded and executed them has been removed.

## Public/Private Boundary

This public repository may contain lesson plans, starter code, starter notebooks, public rubrics, templates, and validation procedures.

It must not contain answer keys, full teacher solutions, hidden labels, private test data, secure scoring packages, or pre-use calibration examples. Those belong in a confirmed-private teacher-key repository.

## Release Check

A repository release is internally consistent only when:

```bash
python scripts/validate_curriculum_structure.py
python scripts/check_required_links.py
```

and the Ready-to-Teach workflow executes the maintained notebooks and starter-code smoke tests for the current commit.

Passing these checks establishes repository consistency, not real-classroom or annual-competition readiness.
