# Validation and Pilot Checklist

Use this checklist before teaching a new cohort.

## A. Repository Validation

- [ ] All module README links open.
- [ ] All listed lesson files exist.
- [ ] Every ordinary lesson contains the seven-step classroom flow.
- [ ] Every lesson has explicit student evidence.
- [ ] BML15 14-lesson sequence links are complete.
- [ ] Bohrium video links open from student accounts.
- [ ] External resources are still available.
- [ ] Annual NOAI / IOAI rules are rechecked.

## B. Runtime Validation

- [ ] Python environment launches.
- [ ] Jupyter or Bohrium runtime opens.
- [ ] Required packages import successfully.
- [ ] Starter notebooks run from a fresh runtime.
- [ ] GPU availability and limits are recorded when relevant.
- [ ] Submission-check scripts run on sample files.

## C. Assessment Validation

- [ ] Round 1 paper-test items have private answer keys.
- [ ] Code-tracing items have private traces.
- [ ] Short-answer items have teacher rubrics.
- [ ] Round 2 tasks have hidden labels in the private repo.
- [ ] Public examples do not leak hidden test answers.
- [ ] AI-assistant policy matches current contest rules.

## D. Pilot Teaching Check

Pilot at least 3–5 lessons before running a full cohort.

For each pilot lesson, record:

```text
Lesson:
Actual duration:
Which step took too long:
Which instruction confused students:
Which evidence was too easy or too hard:
What to revise before the next cohort:
```

## E. Go / No-Go Rule

The curriculum is ready for live student-facing use when:

- lesson structure is complete;
- templates are available;
- runtime opens successfully;
- teacher keys are private;
- no public file leaks answer keys or hidden labels;
- pilot lessons show students can submit evidence within the lesson time.
