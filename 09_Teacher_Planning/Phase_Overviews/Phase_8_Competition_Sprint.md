# Phase 8 — Competition Sprint

## Scheduled Sessions

Sessions 68–75.

## Purpose

Students compress previously learned skills into a reliable competition workflow:

```text
Task recognition
→ baseline and metric choice
→ data audit and leakage prevention
→ time-bounded data engineering
→ diagnosis-first tuning
→ limited automated search
→ efficiency and submission checks
→ full simulation and postmortem
```

## Entry Gate

A student enters Phase 8 only when they can already:

1. build a valid scikit-learn or PyTorch baseline;
2. defend the metric and validation split;
3. detect obvious leakage and submission-schema errors;
4. run one controlled manual experiment;
5. reproduce the baseline from a fresh runtime.

## Video Delivery

The tuning video packages for Sessions 72–74 are pre-class work or separately scheduled resource sessions:

- classical machine-learning diagnosis and tuning: 37 minutes;
- deep-learning tuning: 43 minutes;
- PyTorch schedulers, Optuna, and efficiency: 33 minutes.

The in-class eight-minute Skill Warm-Up is a retrieval/diagnosis task. The full package is not replayed inside that block.

## Exit Standard

Students must submit:

- task-recognition and metric/baseline decisions;
- data-audit, leakage, and feature-engineering evidence;
- manual tuning and, when justified, automated-search logs;
- error and efficiency analysis;
- valid submission and fresh-runtime records;
- a postmortem with a highest-value next action.

A high score without reproducibility, valid validation, or submission reliability does not meet the exit standard.
