# Current Course Map

This repository is organised around official NOAI/IOAI skill demands rather than around completion of one external course.

## Canonical Sources

- `02_Class_Missions/` — canonical lesson content, evidence, and lesson-specific duration.
- `Detailed_Lesson_Sequence.md` — canonical Sessions 1–75.
- `Pacing_Guide.md` — pathway selection and timing policy.
- `Cohort_Pathways_and_Required_Optional_Map.md` — required, selected, optional, and resource-hub decisions.

## Phase Structure

| Phase | Scheduled sessions | Focus | Competition outcome |
|---:|---:|---|---|
| 0 | 1–2 | competition orientation, evidence, GitHub/Jupyter/Bohrium workflow | student can enter the course environment and explain Round 1/Round 2 expectations |
| 1 | 3–8 | Python foundations, functions, control flow, data structures, files, libraries, tracing, and debugging | student can read, trace, complete, and explain paper-based Python code |
| 2 | 9–26 | artificial-intelligence and machine-learning foundations, regression, classification, statistics, metrics, generalisation, trees, and ensembles | student can identify task/model type and solve Round 1 concept/calculation questions |
| 3 | 27–34 | neural networks, forward propagation, backpropagation, optimisation, and convolutional-neural-network concepts | student can trace training logic and calculate key shapes/updates |
| 4 | 35–38 | Round 1 integrated paper-test preparation and mock correction | student can complete timed Round 1 work reliably and repair error patterns |
| 5 | 39–44 | NumPy, Pandas, Matplotlib, data cleaning, feature engineering, and scikit-learn workflow | student can audit data and build a leakage-safe tabular baseline |
| 6 | 45–57 | PyTorch foundations and domain tasks in computer vision, natural-language processing, audio, large language models, and multimodality | student can build and validate task-appropriate PyTorch/domain baselines |
| 7 | 58–67 | project workflow, official-style reproduction, long mocks, submission reliability, and final readiness | student can solve open-ended tasks under realistic time and compute limits |
| 8 | 68–75 | competition sprint: task recognition, data engineering, diagnosis-first tuning, Optuna/efficiency, and full simulation | student can rapidly move from unfamiliar task to reliable baseline, controlled improvement, valid submission, and postmortem |

## Curriculum Layers

| Layer | Count | Use |
|---|---:|---|
| Core scheduled pathway | 67 sessions | full NOAI preparation through competition practice |
| Competition sprint | 8 sessions | late-stage integration and tuning |
| Recommended full pathway | 75 sessions | core plus sprint |
| Mainline Class Mission bank | 155 lessons | required lessons plus deeper practice, remediation, alternatives, and extension |
| Optional Bohrium resource hub | 16 lessons | two full-video missions plus fourteen 70-minute lessons for 北京市十一学校《中学机器学习十五讲》 |

## Scheduling Rule

Do not schedule all 171 public lesson/resource files. Select the target pathway first, then add optional lessons only when diagnostics, entry checks, project evidence, or mock results justify them.
