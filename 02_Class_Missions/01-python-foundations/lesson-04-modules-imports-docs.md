# Lesson 04 — Standard Modules, Imports, and Documentation Reading

**Duration:** 75 minutes

## Timeline

| Time | Block | Student output |
|---|---|---|
| 0–8 min | Skill Warm-Up | Inspect examples using `math`, `random`, `os`, and `sys`. |
| 8–15 min | Talk Robin 1 | Discuss what the import gives the program. |
| 15–22 min | Entry Check | Match modules to use cases. |
| 22–35 min | Core Pattern | Teacher models documentation-assisted use. |
| 35–53 min | Guided Practice | Use docs to choose a function and explain its arguments. |
| 53–67 min | Independent Rebuild | Build a tiny documentation-assisted utility. |
| 67–75 min | Talk Robin 2 + Evidence | Submit documentation note and code explanation. |

## 1. Skill Warm-Up

Students read four small snippets and identify which module is imported and why.

## 2. Talk Robin 1

Prompt: what could the program not do before the import?

## 3. Entry Check

1. Which module is useful for square roots?
2. Which module is useful for random selection?
3. What should you check before using an unfamiliar third-party package?

## 4. Core Pattern

```text
Need → choose module → read documentation → identify function → check arguments → test minimal example
```

## 5. Guided Practice

Students complete a documentation card: module, function, purpose, required arguments, return value, minimal example.

## 6. Independent Rebuild

Create a small utility that uses one standard module and includes a one-paragraph documentation-use note.

## 7. Talk Robin 2 + Evidence

Submit the documentation card, utility code, and one sentence explaining why blind copy-paste is risky.
